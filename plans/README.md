## Recommended execution order

Ordered by leverage (impact ÷ effort), corrective fixes before additive ones:

1. **001** — highest-leverage, two one-line edits, removes off-GPU tweening.
2. **002** — makes the always-on pixel dev honour the ANIM toggle cleanly.
3. **003** — removes competing perpetual loops; establishes the `motion-safe:`
   pattern that 007 reuses.
4. **004** — one-line token consistency fix.
5. **005** — the biggest visible upgrade (scroll reveals); no dependencies.
6. **006** — smooths the project card swap using the existing crossfade recipe.
7. **007** — confirmation pop on copy; reuses the `motion-safe:` pattern.

## Dependencies between plans

- **None are hard-blocking.** All seven can be executed independently.
- **Soft ordering:** 003 introduces the `motion-safe:` Tailwind gate; 007 reuses
  the same idiom. Doing 003 before 007 keeps the pattern consistent, but 007
  also ships its own `@media (prefers-reduced-motion)` fallback, so order is not
  required.
- **005 is standalone** — it adds `src/hooks/useRevealOnScroll.ts`,
  `src/components/Reveal.tsx`, a CSS block, and section-root attributes. It
  touches the same six section files that 006 (Projects) and 007 (Contact)
  touch, so if running in parallel, do 005 first to avoid merge churn in
  `ProjectsSection.tsx` and `ContactTerminal.tsx`.

## Scope guarantees shared by all plans

- **No new dependencies.** The project is intentionally dependency-light
  (CSS-only motion, Web Audio synth, local fonts — see `PROJECT_CONTEXT.md`).
  Scroll reveals use a tiny IntersectionObserver hook, not a motion library.
- **Reduced-motion safe.** Every added or modified animation is gated by
  `prefers-reduced-motion` and/or the app's existing `ANIM` toggle.
- **Composite-only.** All new motion animates `transform`/`opacity`/`filter`
  only; no width/height/layout animation is introduced.
- **Build command:** verify every plan with `npm run build` (which runs
  `next build --webpack` — Turbopack is disabled on purpose per
  `PROJECT_CONTEXT.md` §2).

## What the audit did NOT flag (already correct)

For context, these were checked and found healthy — do not "fix" them:

- Strong easing tokens (`--ease-out-strong`, `--ease-in-out-strong`) already
  exist and match the recommended curves.
- Hover effects are gated behind `@media (hover: hover) and (pointer: fine)`.
- Press feedback uses a subtle `scale(0.97)` on `.pixel-btn:active`.
- Entrance stagger uses composite-only properties with short (<200ms) delays.
- Reduced motion is handled both via media query and a manual `.reduce-motion`
  class toggle.
- No animation is attached to keyboard/high-frequency actions.
- The terminal cursor `animate-blink` is intentional and in scope for nothing.

## Execution notes (all plans executed)

Verified with `npx tsc --noEmit` (clean), `npm run build` (webpack, clean), and
a check of the compiled CSS for every new class. `eslint` reports one error at
`src/app/page.tsx:24` (`react-hooks/set-state-in-effect`), which existed before

Where the implementation deliberately departs from the plan text:

- **002**: steam is hidden (not frozen) when motion is off, because a stopped
  puff looks like a glitch. The screen rect now has a static `fill="#38bdf8"`
  so it stays cyan without the glow animation.
- **003**: the ping dot wrapper got `aria-hidden="true"` (decorative).
- **005**: the hook returns only a ref and writes `data-revealed` directly to
  the DOM instead of holding React state, so a reveal never re-renders a
  section. The reduced-motion check moved entirely to CSS, which now also
  covers the app's ANIM:OFF toggle (`.reduce-motion [data-reveal]`). The
  optional `Reveal.tsx` wrapper was not created because nothing uses it.
  `will-change` was left out, since six permanently promoted sections cost
  memory for a one-shot transition. The revealed state uses `transform: none`
  so no containing block is left behind. A `<noscript>` rule in `layout.tsx`
  keeps sections visible when JavaScript does not run.
- **006**: the hidden layer gets `aria-hidden`, so screen readers don't read
  both views.
- **007**: Tailwind v4 does not apply `motion-safe:` to plain CSS classes, so
  the pop uses `animate-confirm-pop` directly, gated by the
  `prefers-reduced-motion` and `.reduce-motion` rules in `globals.css`. The icon
  is keyed on a copy counter, so the pop replays even when you copy again
  within the 2.5s confirmation window.

## Scroll animation plans (008–013)

Goal: make scrolling feel alive without hurting readability for recruiters.
Agreed direction: subtle base motion plus a few retro moments, mostly
scroll-triggered with a little scroll-linked motion, CSS-first with no new
dependencies. The hero keeps its on-load `.stagger-enter`, the same scope as
plan 005.

How the work splits by technique:

- **Scroll-triggered, once** (008, 012, 013): one `IntersectionObserver` sets
  `data-revealed`; CSS transitions do the motion. CSS scroll timelines can't do
  "play once" (they scrub back and forth with the scroll position), so these
  keep a small observer.
- **Scroll-linked** (010, 011): pure CSS `animation-timeline` (`scroll()` /
  `view()`), on the compositor, no JS. Supported in Chrome/Edge 115+, Safari 26+,
  and Firefox 159+ (enabled by default on 27 Oct 2026). Unsupported browsers
  get the static design.

### Recommended execution order

1. **009** — fixes a real bug: `overflow-x: hidden` on `html`/`body` turns
   `body` into a scroll container, so the "sticky" header has never stuck and
   `view()` timelines bind to the wrong scroller (measured: 6% progress for a
   centred element instead of about 40%). Do this first.
2. **008** — the reveal engine and per-section stagger. Foundation for 012 and
   013.
3. **010** — XP bar (needs 009 so the header is pinned).
4. **011** — timeline spine (needs 009; touches `TimelineSection.tsx` after 008).
5. **012** — pixel-wipe headings (needs 008).
6. **013** — terminal boot sequence (needs 008).

| 012 | 008 | Hidden state is released by the section group's `data-revealed` |
| 013 | 008 | Same; the Contact grid group releases the boot lines |

- Header heights: 136.5px below 640px, 101px from 640–1279px, 55px from 1280px

## Pixel arcade plans (014–020)

Goal: decorative pixel sprites in the empty spots, plus one draggable toy and
two easter eggs. The site stays a recruiter-first portfolio: everything here
is optional decoration, small, and quiet under reduced motion.

Agreed with the owner:

- **Original art only**, in the site palette. No Pokémon or anime characters,
  which are copyrighted and risky on a job-hunting site. Generic game motifs
  (coins, crystals, trophies) are fine.
- **BOT.v2 is the star** (draggable pet), with **a little cat**: one orange cat
  that walks down the Timeline (017) and naps in the footer (018). Neko mode

- Empty spots used: under the Contact terminal (015), the Timeline margins and
  header (017), the footer (018), and section padding bands (019 coins).
- **Phones get the static version**: no dragging, and the pet code is never

### Correction recorded during planning

The plan 008 comment and an earlier explanation said the individual `translate`
property does not create a containing block for `position: fixed`
descendants. It does, while not `none`, just like `transform`. Reveals were
never affected (the revealed state is `translate: none`), but new fixed UI is
portalled to `<body>` (pet) or mounted at the page root (toast). Plan 016
step 6 corrects the comment in `globals.css`.

### Execution notes (014–020)

Executed in the order 014 → 020. Verified with `npx tsc --noEmit` (clean),
`npx eslint src` (clean), `npm run build` (webpack, clean), and 42 automated
checks in headless Chrome against the production build, all passing.

Deviations from the plan text:

- **Pet portal target (016).** The plan said portal into `<body>`. The tests
  showed that ANIM:OFF did not stop the floating pet's blink there, because
  the `.reduce-motion` class sits on the page root `<div>`, not on `<body>`.
  The pet now portals into `[data-app-root]` (that root `<div>`, which has no
  transform), so the ANIM toggle reaches it and `position: fixed` still works.
  The `globals.css` comment says the same.
- **Sleeping cat sprite (014/018).** The planned 14×6 loaf did not read as a cat
  when rendered at 12×. It was redrawn as 14×7 with the head up, ears, and a
  closed eye.
- **PetLayer structure (016).** The drag, fall, and paint helpers are
  module-level functions that receive the refs, as the plan's fallback
  suggested. No ESLint rule needed silencing.
- **Idle detection (016).** `requestIdleCallback` is checked with
  `typeof window.requestIdleCallback === "function"`. The `in` check made
  TypeScript narrow `window` to `never` in the fallback branch.
- The Konami listener and `toggleNekoMode` were added to `ArcadeCorner` in the
  same pass as 015/016, rather than as a separate 020 edit.
